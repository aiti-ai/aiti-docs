扩展开发手册

aiti-agent（pi-web）的业务功能全部以扩展实现，核心只保留挂载点与契约。 本手册是面向扩展作者的完整开发参考：从零写一个扩展 → 调试 → 发布 → 登记的全流程。

① 框架总览aiti-agent 扩展点15 分钟看懂模型：目录约定、加载链路、扩展对象形状
② 动手快速开始：从零写一个扩展跟着教程做出第一个可跑的扩展（server API + toolbar 按钮）
③ 契约参考扩展对象契约 · 插槽全表写的时候随手查：entry 全字段、40+ 插槽与 props 契约
④ API 参考服务端 ctx API · 客户端 ctx APIstartup(ctx) / register(ctx) 两份上下文的完整成员清单
⑤ 专题下方「专题指南」跨扩展调用、数据存储、feature、AI 集成等垂直主题
⑥ 发布部署与热重载 · ext 元数据规范装到实例上跑起来、版本化、登记进文档站注册表

权威源声明

宿主契约的唯一事实源是 aiti-agent 源码（文档可能滞后于代码）：

契约源文件
扩展对象 / 插槽名 / feature / 依赖能力模型lib/ext/types.ts（PiWebExtension / ExtSlotName / ExtFeature）
客户端 ctx 全成员components/ExtSlots.tsx（ExtClientContext）
目录与数据分层实现lib/ext/data-dir.ts
加载器 / 入口文件名lib/ext/loader.ts

发现文档与源码不一致时，以源码为准，并欢迎 PR 修文档。

红线速览（踩过坑的浓缩，展开见对应章节）

  1. 跨扩展调用只走 ctx.services / registerExtService——禁新增 window.__<extId>* 全局穿透（规范）。
  2. 数据只写三层目录（configDir/stateDir/cacheDir）——ctx.dataDir 已移除，访问即抛（规范）。
  3. 插槽 extra 只喂数据，回调一律走服务——随渲染变的值留 props，写操作走 pi-web.* 客户端服务。
  4. onAgentSession 必须幂等——idle GC 与热重载会重复触发（AI 集成）。
  5. client 不 import react——h 与 hooks 由宿主传入；Rules of Hooks：hooks 必须在条件返回之前调用。
  6. version 不手写——唯一事实源是 package.json，entry 里的值只是老扩展兜底。
  7. 懒加载扩展：无 ui[slot] 静态条目的服务触发型扩展，标 clientLazyVia: "service" 豁免静态诊断（懒加载）。
