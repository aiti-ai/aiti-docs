aiti-bridge — the AI Agent Enablement Layer

In one sentence: the MCP bridge turns "page debugging capability" into tools for any AI agent — it configures aiti-devtools usage; enables AI agents; supports aiti-devtools, aiti-devtools-vscode/idea and other plugins to complete injection; and delivers messages directly to the AI agent window inside the IDE via aiti-bridge.

1. Product Composition

PackageFormResponsibility
@aiti-ai/aiti-bridgeLocal bridge service (CLI)Bridge address/pageId configuration, session registration & routing, event broadcasting, IDE AI window hookup; built-in MCP endpoint (stdio shim + HTTP + Streamable HTTP) exposing the page_* / user_* tool families

2. What It Solves

Pain PointSolution
AI cannot see the pagepage_exec (CDP-like commands) / page_snapshot let the AI operate and read the real page
AI needs user cooperationuser_* tool family: element picking, yes/no confirmation, option selection, text input, presence probing, non-blocking notifications
Cumbersome configurationConfig minimization: inspect only needs the AI address passed in; the host assembles the environment (pageId), and the AI window works on open
Hard-coded tokens, multi-connection confusiontoken → instanceId (connection identity, short numeric/alphanumeric), uid → frameId (target frame), combined pageId
Disconnects on refreshinstanceId persistence + TTL retention + secret verification, reload keeps the connection
Messages never reach the IDE's AIIDE plugin + bridge direct connection: the AI agent window receives page events/interaction results in real time

4. MCP Tool Families

page_* (page operations, one-way commands)

ToolDescription
page_execexecute CDP-like commands on the pageId target frame (DOM/CSS/Input/Page/Runtime/Storage/Performance/Browser)
page_snapshotcollect a page snapshot (DOM outline + viewport + framework detection)
bridge_statusbridge connection status, active connections, list of operable pageIds

user_* (human interaction, AI calls the human to the scene)

ToolScenarioWhere the User Answers
user_pick_elementAI asks the user to pick a page elementPage (pick panel + Inspector)
user_confirmyes/no (approve/reject, with reason)AI window answer card
user_chooseoption A/B/C selection (multi-select allowed)AI window answer card
user_inputtext inputAI window answer card
user_presenceprobe whether the user is onlineAI window answer card
user_notifynon-blocking notificationbrowser Notification

Unified semantics: controllable timeouts (frontend countdown + server-synced pause), notifications that reach the user (Notification + title flashing + sound), rejection with semantics (presets + custom reason).

5. Quick Usage

# 1. Start the bridge
npx @aiti-ai/aiti-bridge --port 8777

# 2. Configure any MCP client (one-shot stdio shim registration, idempotent; agents connect via the AITI_BRIDGE_URL env var)
npx @aiti-ai/aiti-bridge --register-shim
# or point an MCP client straight at the HTTP endpoint: http://127.0.0.1:8777/aiti/mcp/mcp

# 3. Tell the AI the target page
# "Use bridge_status to see which pageIds are available, then run page_snapshot on 01234/f0"

6. Security

  • token/secret authentication (verified across SSE / result / event)
  • secret prevents cross-page conflicts: only the original page can reuse its own instanceId
  • dangerous-command confirmation + gesture bridge (transient activation)
  • the bridge endpoint listens on localhost (127.0.0.1) only; page connections are verified via claim/secret
  • external auth for the MCP endpoint: planned adaptation to service-tunnels (auth + token coexistence)
