英文版：Features at a Glance。本文是 aiti-agent 的 features 全览，逐项标注上游 / 自研来源。

aiti-agent 构建于开源项目 pi-web 之上。本文按来源分两层介绍：先列上游 pi-web 原生提供的能力（底座），再逐项展开本项目在其上新增的增强与自研特性；规划中的独有能力单列一节。

开头先给五大招牌能力：多 Agent 会话汇聚、全栈用量与统计、多工作区并行、会话脱离服务进程、输入与消息工作流。其中输入框与消息区（§四）是日常使用频率最高的一条链，细化到「哪个扩展接管了什么契约」。

一、五大招牌能力（先看这里）

🟢 招牌一：把几十种 Agent 的历史会话全部汇进一个界面

这不是简单的「导入」——是把各家 agent 的私有会话存储格式统一解析成一套会话模型，塞进同一个「All Sessions」侧栏里，点开就能看、能续聊、能搜索、能归档：

  • pi 原生会话由宿主直接读取；aiti-pi-agent 通过 pi --mode rpc 拉起多开会话，是网页端跑 pi 的主路径。
  • 通用 ACP 后端 aiti-acp-agent 一个适配器覆盖 25 家内置自动探测的 Agent Client Protocol agent，另有自定义后端面板；授权卡、队列、模型目录都统一呈现。
  • 专业 CLI 驱动各自吃透一家的细节：aiti-codex-agent（exec --json + resume，OAuth/环境变量双认证，直播与冷回放同形工具卡）、aiti-claude-code-agent（keyring 凭据三级裁决登录态）、aiti-cursor-agent（stream-json + --resume，还能只读浏览 Cursor IDE 历史会话）、aiti-codebuddy-agent（长连接 + exec 兜底，control_request 三通道）、aiti-qoder-agent（国际/国内双 CLI、额度、模型目录、任务计划）、aiti-zcode-agent（桌面端内嵌 runtime，长驻 + oneshot 双通道）、aiti-omp-agent（pi 最大 fork 的 RPC 分支）。
  • 附着模式 aiti-attach-agent 用 socket 连上终端里正在跑的 agent 进程，环境变量全自动上桥，排队消息回显、图片附件透传；aiti-testagent / aiti-testagent-native 则把 Java 进程与 Windows 原生进程的调试会话也接进来。
  • 统一管理面 session-manager 内建 23 家 agent 历史解析，All Sessions 侧栏提供 tag 树 + 颜色、收藏、FTS5 全文搜索、agent/tag 高级过滤、归档（.pwarc 快照）与看板视图——新建会话时还能直接挑分支与 Worktree。

结果：终端里用 Claude Code、网页里用 pi、IDE 里用 Cursor、服务器上跑 Qoder——历史会话都在同一个侧栏，不用再记「这条是哪个工具聊的、存哪儿了」。详见 session-manager 与 AI agent 接入。

🟢 招牌二：全栈用量与统计体系

不是一个「本月 token 数」计数器，而是从** token 明细 → 多维透视 → 成本/配额 → 上下文/流畅度 → 会话级汇总**的完整观测体系：

  • 多维用量报表 aiti-ai-usage：按 workspace / provider / model / key / 时段（0–23）/ 日期统计，支持任意维度组合 × 多指标的三种视图——交叉热力表、扁平明细表、手写 SVG 桑基流向图，全部可导 CSV（含 BOM）；数据落独立 SQLite（明细幂等主键 + 日汇总分区重算），事件驱动零轮询。还能摄入外部 agent 的 token 用量（Claude / Qoder / CodeBuddy / ZCode 四源 + codex / opencode / cursor 的 model 归因），不只统计 pi 自己。
  • 余额与配额 aiti-provider-usage：16 个适配器 id（DeepSeek / OpenRouter / Z.AI / Kimi / Codex / Copilot 等），会话信息面板「剩余额度」区块当前会话置顶展开，5 分钟 TTL 总览 + 手动刷新，多 Key 池感知。
  • 模型健康度 aiti-model-check：对每个模型发极小探针，识别可用 / 429 限流 / 异常，解析 Retry-After 等恢复时间，记录历史可用窗口，长期限流到期自动提醒。
  • 上下文与流畅度 aiti-ctx-meter 在输入区实时显示上下文占用比例（四档色阶 + critical 呼吸），点击直达宿主会话统计面板；aiti-cpu-meter 给主线程打出 0–100 流畅度分、颜色分层、可最小化常驻，还带 AI 卡顿调试，并有可注入任意网站的单文件外部版。
  • 会话级统计（🔵 上游 + 增强）每会话 token / 成本 / 工具调用 / 活跃时长汇总，可导出 HTML；再由 aiti-git-trace 把「AI 改了哪些文件、对应哪句对话、哪个操作」也纳入统计与审计。

🟢 招牌三：多工作区并行 + 一个工作区多文件夹 + 固定常用目录

上游只支持「当前工作区」这一个上下文。我们把工作区与文件夹做成可并行、可固定：

  • 多个工作区同时工作：session-manager 的项目下拉列出所有会话派生的工作区，不同项目的会话可同时打开、同时运行，互不打断；侧栏按项目分组、支持隐藏不用的工作区，还能批量把会话搬到新目录或整组归档。
  • 项目与会话置顶：项目可以 📌 置顶并自定义顺序（拖拽调序），会话同样可置顶；置顶项在 All Sessions 树中优先展示，常用项目不用每次翻找。
  • 一个工作区同时开多个文件夹：aiti-folder v2 把文件夹区块升级为动态 dock 实例——每个目录一个面板，可停靠在左栏区块、右栏面板或独立浮窗；项目切换时自动为新的工作目录开一个文件夹实例，也可以从 ＋ 选择器手动加。
  • 📌 钉住目录：文件夹 ⋮ 菜单可钉住，钉住的实例不受自动关闭影响；未钉实例默认最多保留 3 个，超出按 FIFO 挤掉最旧的（配额可在扩展管理的 behavior.folder-quota 调整，1–9）。同一部署子路径下各自独立记忆目录清单与钉住状态，不同实例互不串味。

结果：A 项目的 agent 在跑、B 项目的会话同时在看，两个项目的几个目录都摊在侧栏/浮窗里，常用的直接钉住——真正是多线并行的工作台，而不是一次只能盯一个目录。详见 session-manager 与 aiti-folder。

🟢 招牌四：会话脱离服务进程运行（start detached）

原生的 agent 会话跑在 pi-web 服务进程里：关掉浏览器标签页或断开网络，agent 照常继续跑——这一点本来就没问题；真正会中断的是停掉或重启 pi-web 服务（会话文件还在，但正在运行的 agent 随之终止）。我们做了完整的 agent-starter 体系来解决这一点：Linux/macOS 用 systemd-run 或普通脱离进程，Windows 走 Win32_Process.Create + 管道端点，agent 由独立 wrapper 进程托管并通过本地 socket 与服务通信。于是服务重启后仍能重连回原会话，agent 全程不停；无客户端附着且长时间无输出的会话由 wrapper 空闲回收，不会无限占资源。CLI 接入家族（含 ACP 全系与 CodeBuddy）也在陆续接入这个可脱离宿主。详见 会话与 detachment 说明。

🟢 招牌五：把输入框和消息区做成「不会丢、看得快、听得走」的工作流

上游把输入框当发送控件、把消息当只读文本。我们把这两块每天点击最多的界面做成了有状态、可恢复、可操作的完整链路——每一环都有专门扩展接管，宿主只留薄契约：

  • 草稿不会丢（aiti-draft-keeper）：composer 草稿状态机的唯一所有者（v2 意图契约），每会话一个共享槽位、多标签页同稿；切会话、关页面、崩溃重启后原样恢复，发送失败自动把原文合并回草稿；7 天陈旧槽位自动清理。
  • 输入更快（aiti-ai-input）：两级自动补全（本地规则秒出 → AI 续写兜底）、输入即命令（打「模型」「压缩」直接执行，执行完光标回输入框）、按住说话的实时语音输入（流式识别 + 2-pass 精修 + 多引擎 + 热词）、小屏换行胶囊。
  • 排队可控（aiti-queue-keeper + 宿主队列持久化）：AI 忙时的排队消息有完整面板——拖拽排序、插队发送、转 follow-up、取回编辑、软删回收站与 8 秒撤销、导入导出；队列镜像在服务端 sidecar，重启后逐条决定「重发 / 丢弃 / 稍后」，绝不自动投递。
  • 键盘语义顺手：运行中 Enter 先排队，输入框清空后再按一次 Enter 就把队首升级为插队（steer）；Alt/Option+Enter 是立即插队。空输入 ↑ 取回队列条目或翻会话历史，Shift+↑ 开历史菜单。逐条语义见 §四 的按键速查表。
  • 消息可操作（aiti-msg-smart + aiti-msg-anchor / aiti-msg-nav）：段落、标题、表格行、代码行直接点——复制 / 引用 / 行高亮 / 选项卡；顶部锚点横幅告诉你「屏幕上这段是谁问出来的」，右侧导航条一键到上一条 / 下一条 / 最早 / 最新；整段会话还能分享出去。
  • 听得走（aiti-ai-speek 跟读模式）：点一下 🔊 进入跟读，AI 的每条完成回复按顺序入队朗读，当前句在消息流里高亮并自动滚动（听书式）；浏览器 Web Speech / edge-tts / 本地 ONNX 三档引擎，可克隆音色；关闭跟读时零订阅、零请求。

结果：打字打到一半去查资料、AI 忙时先排三条想法、看长回答懒得读、需要把某一段引用回来——这些日常动作都不用再「手动复制 / 手动记 / 手动翻」。机制细节见 §四「输入与消息」。

三、宿主本体增强（内置于应用，无需装扩展）

🔵 队列持久化与崩溃恢复

上游有发送队列，我们把 steer / 追问队列镜像到 sidecar 文件（lib/queue-store.ts、lib/composer/recovery.ts），服务重启后通过恢复对话框逐条决议，绝不自动投递——配合 aiti-recovery 扩展给出「重发 / 丢弃 / 稍后」的选择。

🟢 移动端完整适配

上游没有成体系的触屏交互。我们新增了移动工具栏、返回手势、右栏状态恢复、顶栏折叠、微信式输入矩阵、思考菜单、长按需常亮等一整套（AppShell.mobile*、ChatInput.mobile*），小屏不是「桌面缩小版」而是重新设计的输入与导航。

🔵 会话分支导航

上游有双分支机制，我们加了 BranchNavigator：树状浏览消息分支、预览后切换到任意叶子节点、从引用处直接跳转到对应分支。长会话反复试方案时不再迷路。

🔵 MCP 密钥脱敏（宿主侧）

设置面板展示 MCP 配置时，对 URL / 参数中的凭据自动打码，env / header 的敏感值根本不送到浏览器（lib/mcp-secrets.ts）。与 pi-secret-mask（对话侧脱敏）是两道不同的防线。

🟢 会话删除进回收站 + 分支批量删除

上游的删除是直接删。我们把会话文件移入 XDG 桌面回收站并附还原信息，可从文件管理器找回；另提供「按项目删除全部会话」，级联清理子 agent、脱离运行的 wrapper、置顶与归档记录，避免留一堆孤儿进程。

🔵 完成通知体系

运行结束浏览器响铃一次且不重复，favicon 加待读角标，支持 Web Push 桌面通知——即便切到别的标签页干活也不会错过结果。

🔵 自动命名与运行结果判定

首轮对话后自动生成会话标题；新增统一的运行结果判定（失败不再误报「任务完成」），让侧栏状态与通知语义一致。

🟢 外部端续写时提示刷新

会话文件可能被其他端续写（如 zcode 桌面端接着聊）。消息区会出现「刷新会话内容」提示，点一下重新加载，不用重开会话。

🟢 任务清单进度

多步任务在输入区显示 done/total 进度条，点开是任务清单，运行中也能一眼看清还剩几步。

🔵 Git worktree 工作区增强

上游能切 worktree，我们进一步做到：会话按项目与 worktree 分组排序、支持重命名与拖拽、session-manager 新建会话时提供分支 / Worktree 选择器，并与 aiti-git-ops 的写操作闸门联动。

🔵 聊天外观与输入框连贯性

内容宽度（820–2000px）、字体、终端主题等外观偏好持久化；草稿跨会话保留、休眠压缩、收缩链动画，中断后的待发提示词可恢复（与 aiti-draft-keeper 配合形成完整的 composer 状态机，见 §四）。

🔵 其他细节增强

一键在系统文件管理器打开工作区；Debian 风格版本比较的自更新提示；多层对话框 Esc 只关最顶层（stacked-dialog）；每会话统计与 HTML 导出；文件管理器直达与查看器窗口聚焦转发等。

四、🟢 输入与消息（全部自研扩展）

输入框与消息区是每天点击最多的两块界面。上游把它们当作「发送控件 + 只读文本」，本项目把这条链路做成了有状态、可恢复、可操作的完整工作流：输入 → 补全 → 排队 → 发送 → 阅读 → 引用 → 听读。每一环都由专门的扩展接管，宿主只保留薄契约（数据与 RPC 留在 core，UI 与策略在扩展里），任一扩展关停都能回落到可用状态，数据不丢。

输入框按键语义（速查）

运行中的 Enter 语义是本项目对上游的重定义：上游默认 Enter 直接插队（steer）、Alt+Enter 排队；本项目反过来把非破坏性的排队设为默认，插队才需要显式按键。

场景按键行为
空闲Enter发送（设置里可改为 Ctrl/Cmd+Enter 发送）；Shift+Enter 换行
运行中 + 有文字Enter排队为 follow-up，本轮结束后按序自动发送
运行中 + 有文字Alt/Option+Enter立即插队（steer），优先于当前轮处理；后端不支持 steer 时自动降级为排队
运行中 + 空输入Enter / Alt+Enter把队列里第一条 follow-up 升级为插队——回车排队，再回车插队
运行中Esc中断当前运行（菜单打开或输入法组合中时不触发）
空输入↑有排队消息：取回最后一条到输入框编辑（发送后放回原队列位置）；没有排队：像 shell 一样向上翻会话输入历史
空输入Shift+↑打开输入历史菜单，↑/↓ 浏览、Enter/Tab 选中
取回编辑中↑ / ↓在当前队列条目之间切换编辑，发送仍各自放回原位
输入框/斜杠命令候选（扩展 / 提示词 / 技能统一检索），↑↓←→ 导航、Tab/Enter 补全
输入框@文件候选，↑/↓ 导航、Tab/Enter 补全
输入法组合中Enter只确认候选词，不会误发送（组合结束后留短暂宽限）

输入框 AI 智能（aiti-ai-input）

两级自动补全：停止打字 700ms 且光标在末尾时，输入框里以灰字给出下一句——Tab / → 接受，Esc 或继续打字取消。

  • L0 本地层（零模型、秒出）：先查本地收藏的提示词与会话历史输入，服务端做前缀匹配，命中即灰字直出并标出「↦收藏 / ↦历史」来源，不请求模型。
  • L1 AI 层：L0 未命中才用同款模型发一个小请求，0.4–2 秒后给出更长的续写。
  • 治理三件套：总开关、localOnly（只跑 L0，零出网）、最小触发长度（默认 3，中文按 1.5 加权）；上下文预算另有低/中/高三档，续写不会悄悄把长上下文全塞进去。

收藏联想（suggest）：输入前缀即弹候选面板，静态候选优先——命令 ⚡（rank 0）、提示词 📌（rank 1）、应用命令（点击直接执行而不是填文本），都不命中时才走 AI 兜底。桌面是固定弹窗（↑↓ / Tab / Enter / Esc 全键盘），小屏是文档流建议条（点按生效）。联想源可扩展：任何扩展都能注册自己的 provider，suggest.looseLen 控制短输入严格过滤的阈值。

语音输入（三层，逐层可选）：

  1. 听写检测 + 修复（默认关）：纯浏览器事件特征（beforeinput 的 inputType + 节奏）判断文字是否来自语音或高速输入，零服务端依赖；命中后输入框上方出现「🎤 正在帮你检查修复转写错误」，发送时只对歧义处做 AI 拼写修复、给替换建议，不整体重写。
  2. 🎤 实时 ASR（按住说话）：流式 WebSocket 识别 + VAD 自动切句（约 0.7s）+ 伪实时分句（SenseVoice），松手后走 2-pass 离线精修（Qwen3-ASR）。
  3. 引擎可插拔：自建 8767（FunASR / Qwen3 / GLM，真流式 + 模型级热词）、讯飞本地桥 8768、百度 / 硅基流动 / Azure / 任意 OpenAI 兼容端点；面板里切换引擎，key 只回显末 4 位。自建服务可由扩展经 aiti-cmd 的 PTY runner 自动拉起（熔断 60s、防重 120s），不用手工起服务。

热词、统计与小屏：session-manager 的 hotwords 服务按工作区自动提取术语，与用户词库（≤500 条）合并后按 ws 推送给识别引擎做偏置（哈希 key + 10 分钟 TTL 防抖）；右栏「语音流量统计」按引擎看用量。触屏设备上输入框聚焦且光标不在行首时，上方常驻「⏎ 换行」胶囊，补上手机键盘没有 Shift+Enter 的缺口；桌面不受影响。

输入框即操作中枢（命令直达，aiti-ai-input + aiti-app-center）

在输入框里打一个词就能直接干活：输入「模型」→ 联想区弹出选择模型候选，点一下就在原地弹出模型选择框，选完自动关回来、光标还在输入框，不用去工具条、不用离开输入流；输入「压缩」→ 直接触发当前会话的上下文压缩（与会话信息面板的压缩按钮同一链路，压缩中/排队中不重入）。

机制上这是一条固化范式：任何扩展在 commands 命令目录槽注册一条目即同时获得 App Center 应用卡与输入框命令候选（可钉住、可搜索、点击即执行、不往输入框塞文本），宿主零改动。已铺开的能力包括打开终端（aiti-folder）、容器面板（aiti-containers）、模型与压缩（本项）；后续会话切换、思考强度、导出、分支等都可按同一范式挂上来——愿景是把「一句话/一个词唤起任何操作、执行完自动回到输入框」做成工作台的默认交互。

配套的关键词也不再由应用中心写死：扩展用条目级 meta.keywords / 扩展顶层 keywords 自带搜索词（中英别名都行），App Center 只负责消费与兜底——新扩展自带词汇，不会被「忘记登记」漏掉。

输入草稿保存（aiti-draft-keeper）

一句话：崩溃可以带走页面，带不走你打到一半的话。 它是 composer 草稿状态机的唯一所有者（v2 意图契约），但并不只是「定时存一下」：

  • 每会话一个共享槽位：多标签页打开同一会话天然共享同一份草稿；切换会话、关页面、刷新、崩溃重启后原样恢复。恢复等服务端水合完成（pi-web:hydrated 信号 + stage 重放）才动手，避免被首屏重渲染抹掉。
  • 只写真实输入：onChange 只在内容真的变化时写（快照与已知内容相同就不写），发送后的清空延迟 300ms 确认；扫描只读不写——框空但有存储就静默恢复，存储比已知多就同步进框，恢复那一轮的 onChange 直接跳过，防止「一恢复就删」。
  • v2 契约的唯一写入口是 applyIntent：临时会话提升为真实 id（sessionCreated）时，临时草稿作废、窗口期内新输入重定向到真实槽位，并清掉 new:<cwd> 整族内存副本，避免已发送内容残留在「新会话」框里；发送被拒绝（rejected）时把提交的原文合并回草稿（提交在前、原稿在后）再写回输入框。
  • 清理与迁移：注册时一次性 pruneStale() 清掉 7 天未写入的槽位（含旧 per-tab 残留与无时间戳格式），不做轮询；旧 crashrestore-<key>-<tabId> 首次读取时自动并入按 cwd 共享的新槽位。

价值：切会话去查资料、开第二个标签页对照、AI 回复时顺手改需求、浏览器崩溃、发消息失败——这些日常动作都不会再吃掉你打了一半的字。

队列面板（aiti-queue-keeper）

AI 忙的时候可以先把想法排上，而且队列本身是可操作的：

  • 完整面板：横幅折叠 / 展开、条数与「全部取回」；行操作支持 ↑↓ 移动、拖拽排序（桌面 HTML5 + 移动触摸两套实现）、steer 插队发送、转为 follow-up、单条取回编辑、删除。
  • 可反悔：软删进回收站（可恢复 / 彻底清空，带确认文案），删除后 8 秒内一键撤销；导入 / 导出 JSON（导入先暂存，逐条决定恢复哪些），空队列也有通知反馈。
  • 零自有存储：队列镜像、sidecar 持久化、12 个 RPC 与回收站都在宿主 core；扩展只做 UI，操作统一走 actions 原语。关停扩展只是回落到宿主的上游同形横幅，任何状态下数据都不丢；queuePanel.enabled 关闭实时生效，不用刷新页面。
  • 与草稿保管员协同：两者不直接对话，全部经 core 契约交汇——草稿恢复项与队列恢复项在同一个恢复对话框合流；草稿的「重新排队」经 core queueFollowUp 入队（由本扩展渲染）；行内取回经 core edit-intent 写回输入框（草稿保管员通过 onChange 看到同一个值）。

宿主的队列持久化是另一半：steer / follow-up 队列镜像到 sidecar 文件，服务重启后通过恢复对话框逐条决议（重发 / 丢弃 / 稍后），绝不自动投递；aiti-recovery 把中断会话与待决议队列一起呈现。

运行结束时，输入框旁的「继续」按钮一键发送「继续」；队列非空时同一按钮变成「立即运行队列」——按顺序投递全部排队消息。从队列取回编辑的条目发送后回到原位置，↑/↓ 可在队列条目之间直接切换编辑。

消息智能（aiti-msg-smart）

把 AI 的消息从「只读文本」变成「可点的富文本」：

  • 点段落 / 标题 / 列表 / 表格行：弹操作卡片 → 复制全文 / 引用（整段或单句）/ 选项按钮（是·否、A·B，点击即预填回复）。
  • 点代码行：复制该行 / 引用该行，并在原文中高亮圈选该行（滚动跟随）；hover「引用单句」按钮会在原文里高亮对应子句。
  • 内联代码：点一下直接复制，另有可扩展的小动作层（默认「复制」，其他扩展可追加动作）。
  • 识别器可插拔（features 可逐项开关）：封闭问句 → 是/否与 A/B 选项；文件/目录路径 → 📂 打开 + 📁 定位（存在性校验，404 静默）；http(s) 链接 → 新窗口打开；任意段落 → 复制 / 引用；划选文字 → 弹层复制 / 引用回复（当前会话）/ 新会话引用。主 cwd 未命中时还能经 aiti-git-trace 的会话识别仓跨仓分辨文件。
  • 边界清晰：core 只提供「段落点击广播 + 宿主能力透传」的薄扩展点，识别、决策、UI 与文案全在扩展里；新增可点场景只需扩展声明可点标签，不用改 core。其他扩展还能注册 msg-popover-action / inline-code-action，往弹层里追加自己的动作。

消息锚点与导航（aiti-msg-anchor + aiti-msg-nav）

长会话的两件「空间定位」工具，纯前端、零服务端 API：

  • 锚点横幅：每个用户输入与其后的回复构成一个回合段，滚动时横幅跟随当前视口顶部所在的回合段，显示「当前屏幕内容由哪条输入生成」及序号/总数，点横幅平滑跳回该输入；锚点输入已经出现在屏幕里时自动隐藏，停止滚动 6 秒后淡出。可切换为第一条输入 / 最近输入 / 会话标题。
  • 导航条：到最早（触发懒分页自动加载更早消息并保持视口）、上一个 / 下一个用户输入、到最新；长按「到最新」用 Screen Wake Lock 保持屏幕常亮（不支持时自动降级）；整条导航条可拖到消息区任意位置并记住位置。

消息分享（aiti-msg-share）

整段会话、单条消息、选区、文件与图片都能通过可插拔目标分享（Gitee / 图床 / 对象存储 / 笔记归档），上传前自动做密钥脱敏，生成链接附二维码。目标不是硬编码：审计目录可以当远程 overlay 热更新；还有 share-sink 扩展点，其他扩展能把分享内容收进自己的收藏或命令库。

跟读模式（aiti-ai-speek）

「跟读」不是给单条消息点播放，而是把阅读模式整体切成听书模式：

  • 开关在工具条：🔊 关 = 真正的零开销（不订阅 SSE、不拉消息列表、不发请求，喇叭上也不显示消息数）；点开 = 本会话进入跟读，AI 每完成一条回复就按顺序入队，不打断正在读的那条。
  • 播放条常驻：⏮ 上一句 / ⏯ 播放暂停 / ⏭ 跳过本条 / ⏹ 停止（清队列回阅读模式），语速 0.75–2x、实时切换音色、显示队列「2/5」；切到别的会话再回来从上次位置续读，页面刷新后也能确定性恢复（不依赖组件时序）。
  • 跟读高亮（听书式）：当前朗读的句子在消息流里被圈选，并按 smart（默认，智能跟随）/ always（始终拉回）/ off（只高亮不滚动）三种策略自动滚动；用户主动滚远时不会把人拽回去，而是给「跳回读位 / 从本页开始读」两个按钮。
  • 三档引擎：浏览器 Web Speech（零依赖兜底）、edge-tts（服务端合成，音色更自然）、本地 ONNX（Hojo-TTS-Light 40M/80M，CPU 可跑；40M 带 17 个内置音色，80M 支持用 3–30 秒参考音频克隆音色，自动装 venv 与模型，空闲 30 分钟退出）。本地服务对外是一个 OpenAI 兼容的 /v1/audio/speech，默认 8768（占用时自动顺延），其他客户端也能复用。
  • 省流与细节：按句预取（当前句 + 后 3 句），合成结果按「引擎 + 音色 + 语速 + 文本」进缓存池，重播不重新合成；短回复阈值（默认 8 字）避免「好的」「收到」也念；朗读内容可切「全文 / 要点」；开启跟读时可向会话注入一次「朗读模式」提示词（让 AI 先给结论、更口语化，便于听）；后台标签页是否继续读也有开关。
  • 不只是聊天：编辑器与文件预览的 🔊 按钮能把文件正文分段朗读并做行级跟随；其他扩展可以调用 aiti-ai-speek.speak 读一次性提示，或直接用服务端 tts 服务合成音频。

提示词（aiti-prompts）

常用提示词收藏成分组片段库，支持从历史会话提取、输入即存，还能接收 aiti-msg-share 的收藏内容；重复话术一键复用。

追加系统提示词（aiti-append-system）

在网页里直接编辑全局与项目两级的「永久记忆」规则文件，也能让 AI 代起草，不用登服务器手改文件。

定时任务（aiti-ai-schedule）

常驻调度器：扩展可声明式注册周期任务，用户与 AI 都能建计划（cron / 间隔 / 一次性），三种执行模式 + AI 自建计划工具 + 管理页；备份、模型探测等扩展都挂在它上面。

会话搜索（pi-session-search · pi 插件）

给 AI 一个搜索历史会话的工具：上下文被压缩后，agent 可以自己翻回「上次聊到哪」的原文并接着做，等于给会话加了长期记忆索引。

五、🟢 模型与用量（全部自研）

模型添加向导（aiti-model-wizard）

目录搜索（models.dev + 国内 AI 目录，中英文，贴 API 地址也能反查）→ 填 token → 连通性测试（2xx / 429 均算通过）→ 选或输模型 → 写 models.json；找不到时支持从任意文档/代码片段自动提取 baseUrl 反向匹配，缺 v1/v2 前缀能自动探测补全，靠 OpenAPI / 模型前缀推断品牌。编辑时 token 打码不返回前端；导出/导入配置走白名单字段，永不带明文 key。

多模型配置导入（aiti-models-import）

扫描 Codex / ZCode / OpenCode 里已有的 provider 与模型配置生成草稿，首次启动一次性引导导入；所有落盘经向导的 saveBatch，可一步撤销，绝不直写 models.json。

模型列表与多 Key 轮转（pi-models-combo · pi 插件）

精简模型列表（按需要过滤显示），多把 API Key 粘性轮转以避开限流，还能把多家提供商聚合成一个「组合模型」——同一个模型名背后按策略分流到不同后端。

提供商余额（aiti-provider-usage）

16 个适配器 id 的余额 / 配额查询，会话信息面板常驻「剩余额度」区块且当前会话置顶展开；总览 5 分钟 TTL 缓存 + 手动刷新，多 Key 池总量感知。

Token 用量报表（aiti-ai-usage）

见「招牌二」——多维透视、桑基图、CSV、独立 SQLite、外部 agent 用量摄入，是全套统计体系的核心。

模型健康检查（aiti-model-check）

极小探针消息探测每个模型的可用性 / 限流 / 异常，解析限流恢复时间，记录历史可用窗口，长期限流到期时本地提醒（零额外探测开销）。

上下文指示条（aiti-ctx-meter）

桌面 compactLead 竖向比例条 + 小屏 modelInfoLead 前导位，四档 urgency 色阶与 critical 呼吸效果，点击直达宿主会话统计面板。

最近使用模型（aiti-model-recent）

纯 service 扩展（零 UI）：模型选择器 recent 段同步取数，pick 事件入 LRU；与旧实现的 localStorage key 兼容，零迁移。

六、🟢 安全与数据（全部自研）

密钥脱敏（pi-secret-mask · pi 插件）

「随手贴，不泄密」：贴进 prompt 的 token / API key 在发给模型前自动变占位符，工具执行时才还原真值；确定性脱敏 + /secret 命令管理。适合临时值，不跨会话持久。

密钥保险库（pi-secret-vault · pi 插件）

需要跨会话、加密落盘、模型按别名查询时用持久版：模型只看到 rsec_<hash8> 令牌，增删改与查看明文始终由人操作。与 mask 共享同一引擎、同会话互斥（vault 优先时 mask 自动停用）。

保险库管理（aiti-secret-vault）

Web 侧管理界面：列别名 / 新增 / 轮换 / 揭示 / 删除，锁定解锁，keyfile 与系统钥匙串两种解锁方式，还能查看每个会话挂载了哪些别名——值永远不进 AI 对话。

配置安全网（aiti-configs）

AI 或人改坏配置、改坏扩展时有 diff 可看、有锅可回、一键恢复；系统崩溃时独立命令行哨兵不依赖出问题的系统本身兜底。

数据快照备份（aiti-backup）

针对 state 层大体积数据（会话等）的硬链接增量快照：每轮一个完整时间点 + manifest 完成标记，同路径同大小同 mtime 的文件零拷贝链接；目标盘不支持硬链接（exFAT 等）时自动降级为全量复制。源严格只读（不跟随符号链接），扫描与复制在独立子进程里跑、进度走事件总线；中途被杀只留 .tmp-* 由下轮清理，每源一把运行锁；keepCount 轮转只删快照目录。

设备互连（aiti-pair）

连到同一个桥的设备（手机浏览器 / 其他电脑 / agent 会话 / 注入页面）互发消息、互传文件——跨设备协作不用自己搭中转。

恢复向导（aiti-recovery）

会话中断后，排队消息与中断任务逐条给出处理选择；红线是绝不自动投递，续跑只发「继续」，恢复完全由人决定。

七、🟢 Git、调试与基础设施（全部自研扩展/插件）

页面内 AI 调试助手（aiti-devtools）

核心能力：把任意网页变成 AI 可协作的调试现场。点选页面元素即把结构化信息直达 AI；AI 可执行类 DevTools 的 DOM / CSS / 输入 / 性能操作，还能反过来向用户提问、请用户帮忙点选元素——人与 AI 在同一页面上并肩排障。配套 vite / webpack / nuxt 载体插件、VS Code 扩展与浏览器扩展，桥协议由独立核心包统一提供。

Git 变更审核（aiti-git-review）

专职审核未提交代码：Monaco diff 工作区（并排 / 合并 / 纯新 / 大纲），行级标注分「必须改 / 建议 / 疑问」，anchor 标志行重映射保证边审边改标注不失效，汇总终审清单；aiti_review_* 工具只注入评审会话，日常会话零工具负担。

Git 写操作（aiti-git-ops）

白名单 git 写引擎：checkout 预检、stash、plan 断点、全程审计、changed topic；供文件浏览器与会话管理器消费，让 AI 能安全地做 git 写操作而不弄丢工作。

AI 变更追踪（aiti-git-trace / pi-git-trace）

编外追踪仓 .aiti-trace，无 git 的目录也能 autoInit；每次改动按 op 编号做 before/after 双 commit，文件 ⇄ 消息 ⇄ 操作全链路可查，随时一键回撤，影子仓还能 compact 瘦身。两者同源：aiti-git-trace 是工作台扩展（文件浏览器里每个文件自带「⎇ 文件时间线」，单文件变更历史直查），pi-git-trace 给纯 CLI 用户。

服务隧道（service-tunnels）

本机服务一键公网可达：端口自动发现（服务识别 / 自定义名），五种暴露模式（隧道 / vhost / 混合 / 路由器映射 / IPv6 直连），认证网关（portal / TOTP / 人脸声纹），DDNS 自动解析与网络体检 doctor。这是本项目独有的暴露层能力。

命令中心（aiti-cmd）

一个扩展三个应用：命令收藏（分组 / 标签 / 词库 + 一键执行）、运行中（终端会话 / agent 命令 / 执行记录）、真 PTY 终端；另有消息识别、输入框运行态势入口、跨扩展统一执行出口，终端会话在重载与重启后仍存活。

容器管理（aiti-containers）

一个面板管容器、镜像、卷、网络与 compose 项目（docker / podman / nerdctl），启停、日志、清理全覆盖，并与服务隧道的端口页联动。危险操作走同一套确认协议：界面首次点击进入「5 秒内再点一次确认」，API 未带 confirm:true 返回 428 + 危险说明，AI 必须先把动作原文摆给用户、拿到明确同意才能重调。

终端桥接到浏览器（pi-web-bridge · pi 插件）

终端里照常跑 pi TUI，敲一个 /web 即把同一会话实时开在浏览器里，双向 IO（prompt / steer / follow-up / abort / 切模型）、排队消息回显、图片附件透传——终端与网页随时交接。

无头服务器图形环境（aiti-ui-env）

给没有显示器的服务器分配虚拟桌面：4 态模式裁决新启动 MCP / 应用的显示环境，Xvfb + openbox + AT-SPI 虚拟屏，VNC-on-web 与 RDP-on-web，Linux / Windows / macOS 三平台服务化；VNC 密码由 VNC server 自己认证，桥只透传。

远程调试注入（aiti-debug-inject）

把另一个工作台实例的调试器注入本实例页面，方便开发者远程排查线上问题；服务地址是扩展管理里的文本 feature，默认关闭、按需开启。

流畅度检测器（aiti-cpu-meter）

见「招牌二」——0–100 流畅度分、颜色分层、最小化常驻、AI 卡顿调试。三条注入通道：service-tunnels 代理站点直接注入、任意站点走 bookmarklet、跨实例注入（service.url + inject.enabled）；window.__aitiCpuMeter.report() 给出分数、长任务、LoAF 脚本归因与会话级时间加权平均分数——扩展内版 + standalone 单文件版双产物。

🟢 视频工作室（aiti-video-studio）· 🟡 内测中

🟡 内测中：未随发行版分发、未上架 npm；当前仅在实验区源码部署（建议 dev 实例），生产使用请等正式发布。

把「演示视频」变成一门可重现的工程，而不是靠人手录屏剪辑。核心思路：AI 在创作期写脚本，运行时零 AI——你打字，它出片。

  • 一条链路到底：AI 读视频创作 skill → 探索目标站点（dry-run 探针）→ 写 scene.json（步骤 + 旁白节点 + 展示层）→ /dryrun 校验 → TTS 先行（内容哈希缓存，时长已知）→ 在 chromium 里确定性回放并采集画面 → ffmpeg 合成 → final.mp4 + 字幕 + 章节 + 报告 + 波形图。也可用面板里的结构化编辑器，不写 JSON 也能做片。
  • 逐帧确定性录制：CDP 在绘制时刻抓 JPEG 帧再拼接（无白场、文字锐利），另有 recordVideo 兜底；每一步在屏幕上停留的时长严格等于其旁白时长，因此画面与声音天然对齐。
  • 真实交互的现场感：伪光标环 + 点击涟漪（可只在点击时出环）、导航后仍存活；四类特效（聚光灯 / 聚焦环 / 周遭压暗 / 彩带）按旁白自动定时。
  • 十六种覆盖层块：下三分之一条、标题卡、标注、徽标、箭头、图片卡，外加 13 个内置块（推文、macOS 通知、YT 下三分之一、数据图表、Spotify 卡、Logo 片尾、IG/TikTok 关注、Reddit 帖、流程图、应用展示、UI 3D 揭幕、自定义本地 HTML）；四种转场与三种滤镜包（flash-white / chromatic / glitch），转场时长保留不抢旁白。
  • 后期一应俱全：导出后用 zoompan 做镜头推拉（框准确、覆盖层不受影响）+ 可选动态模糊、屏幕工作室式画框（内边距 / 圆角 / 投影 / 渐变背景）、CAS 锐化、BT.709 编码、硬件编码器自动探测（nvenc/qsv/vaapi/videotoolbox 均真实试编）、背景音乐叠加 + EBU R128 响度归一。
  • 多语言成片：同一份脚本可按语言出多条片，每语言独立配音映射与字幕；面板里切语言即可。
  • 人类参与但可控：user-confirm 步骤会在页面上弹确认/选择/输入卡并等人点，等待过程可选择剪掉或保留在片里；另有两个显式 AI 触发点：ai-decide（让 AI 从实时页面证据里选一个值写进脚本变量，带问人兜底）与 onError: ai-fix（失败步骤由 AI 出 JSON 补丁并回写 scene.json，带熔断上限）。
  • 真机脚本可扩展：步骤可引用项目内 scripts/*.mjs，一个模块导出多个入口；项目信任绑定到脚本树哈希，改动即失效。面板内置 CodeMirror 编辑器。
  • 隐私遮挡：场景级或步骤级的 CSS 选择器 + 马赛克 / 模糊 / 遮盖规则，img 与 video（摄像头画中画）都能遮，录制里真的不出现。
  • 完整交付物：final.mp4（H.264/AAC）、final.srt、final.vtt、chapters.txt、report.md、waveform.png、timeline.json、meta.json、逐步截图，以及 9:16 / 1:1 / GIF 附加格式与片片段提取（mp4/gif）。
  • 工程化管理：项目侧栏（搜索 / 筛选 / 状态 / 置顶）、模板、重命名（显示名与目录 id 联动迁移）、复制、导入导出、删除进系统回收站、运行清理、并发队列批量录制。
  • 直播演示模式：独立字幕条窗口（由 aiti-desktop-widget 承载）+ 当场语音播放，演示时可暂停 / 恢复 / 跳过当前步 / 跳到任意场景 / 停止；录制模式保持确定性，拒绝这些控制。
  • 播放器：播放/暂停、±3 秒、上一/下一场景或章节，场景选择器由 timeline.json 生成，点任意场景即定位播放。

TTS 引擎可选 edge（本地 CLI）、任意 OpenAI 兼容 /v1/audio/speech、ElevenLabs、Gemini、Sarvam、以及可选的本地 kokoro-js。设计上借鉴了 Argo（@argo-video/cli，MIT）的思路（TTS 先行定节奏、内容寻址缓存、覆盖层词汇表、jpeg-stitch 采集等），并明确拒绝了几项（远程第三方 HTML 注册表、WebGL 预渲染转场、波形编辑器），理由写在扩展文档里。详见 aiti-video-studio。

🟢 工作流程实验区（未公开发布）

这几个扩展还在实验区磨练、未随发行版分发，但代表一个很不一样的方向——把「先写方案再改代码」变成工具能感知、能提醒、能追责的流程：

扩展作用
aiti-plan-first（方案先行）靠 aiti-git-trace 事件感知（推-听架构、零扫描）：Markdown 变更时弹绑定向导（命名优先匹配方案）、大改却未跟方案时提醒、方案领先于代码时提醒「先做方案」；front-matter 作为标签事实源，会话列表行前部带 📋 绑定标
aiti-plan-review（方案采认）Plan-Sandbox 的采认收尾 UI：读 review.json 契约列出「声明 vs 其他」差异，可采认选中并关闭沙盒 / 仅保存 / 全部丢弃；带沙盒历史（重新提取 / 重用 / 销毁）
aiti-echo-agent（回声后端）多 agent 前端的会话 provider 插槽演示后端，用来验证新后端接入链路
aiti-updater（升级面板）🟡 内测中：版本检查 → 升级触发 → 原地观察（SSE）→ 跳服务管理；服务注册 / 升级 / 服务管理统管，安装与反代通过 service-tunnels 配置收口
aiti-proc-tree（子进程管理）📋 方案评审中：以 pi-web 宿主为根，树形列出终端 / 隧道 / 子代理 / 外部 agent / detached 会话等全部派生进程，带 CPU / 内存 / 时长，可结束单进程或整棵子树（对齐 Chrome 任务管理器）；打开才采样

另有 aiti-bridge-probe（桥连接诊断）与 demo-lazy（懒加载演示）两个诊断/示例用途的实验扩展。

研发与模型实验（🟡 内测中）：aiti-codehub 把云效 / GitHub / Gitee / GitLab 的工作项与代码库收进工作台（多账号、AI 工具、工作区克隆）；aiti-model-gateway 把已配置模型导出为 OpenAI 兼容 API，供外部 agent 用网关 token 接入。两者都未随发行版分发。

十二、小特性合集（顺手好用的补充功能）

下面这批功能体量不大，日常用起来很顺手。它们是前文未展开的补充条目，均为 🟢 自研（少数是在上游基础上再打磨，标 🔵）。

聊天与消息的小心思

  • 🟢 出错了直接问 AI：错误/警告通知条上带「Ask AI」按钮，一键把报错原文喂给 agent 排查，不用手动复制粘贴。
  • 🟢 复制按钮两头都有：助手消息的复制按钮同时挂在消息顶部与底部；鼠标悬停的操作按钮挪到消息左下角，长消息不用滚回顶部。
  • 🟢 bash 执行中也能分叉：命令跑着的时候 fork 按钮不隐藏，点击会被暂存而不是丢失——这是专门修过的体验细节。
  • 🟢 编辑中的提示词有视觉提示：从某条消息「从这里编辑」时，草稿区显示遮罩预览，避免把预填内容和自己输入的内容搞混。
  • 🟢 消息里的操作卡片更规矩：工具调用的扁平参数改成逐行展示，codemode 调用显示脚本本体与其工具调用，MCP 调用标出 server/tool 并缩进 JSON 结果。
  • 🟢 发前扫描（composer gate）：消息离开输入框前，aiti-secret-vault 用比自动打码更严的规则再扫一遍，命中则问「打码后发送 / 原样发送 / 取消」——打码会把值先加密进保险库、文本换成稳定占位符，模型永远看不到明文。
  • 🟢 压缩撞忙自动排队：压缩请求到达时会话正忙，就先把请求停在服务端（按会话 id 排队）而不是浏览器标签页，会话空下来自动接上——关掉标签页也不会丢。
  • 🟢 双币计价显示：界面语言为中文时，成本按 $xx（¥yy） 双币显示（汇率走服务端 24h 缓存），其它语言保持 $xx；记账单位始终是 USD，不改变计算口径。
  • 🟢 新会话带着上下文走：输入框旁的「新会话」以当前完整上下文 fork 一个新会话并发送当前输入，原会话照常继续跑，互不影响。
  • 🟢 会话之间捎话（/relay）：/relay <会话 id> <消息> 把消息投给另一个存活的 backend 会话，回复再注回当前对话——两个 agent 互相交接不用复制粘贴。

导航与布局

  • 🟢 右栏三档展开：右栏展开按钮在「停靠 → 加宽 → 全屏」三档间循环，一个按钮搞定从瞄一眼到专注看。
  • 🟢 面板缩放滑块：设置里可调侧栏与右栏的 UI 缩放比例，面板字体/控件过大或过小都能自己调。
  • 🟢 主栏与文件栏可拖动调宽：布局宽度可持久化，不是固定死的比例。
  • 🟢 顶栏收口：系统提示词与调试面板都补了标题栏关闭按钮，调试入口统一进顶栏顺序系统。
  • 🟢 欢迎页 recent-on-top：欢迎页顶部卡片区自适应撑开，最近会话置顶，打开就是接着干。
  • 🟢 一处停靠四处可用：同一批面板可停左栏区块、右栏面板或独立浮窗，⋮ 菜单全线统一（浮窗 / 左栏 / 右栏 / 上移 / 下移 / 关闭），位置记忆跟随部署子路径隔离。
  • 🟢 顶栏自己排：顶栏顺序可自定义——显隐、上移 / 下移、插入分组间隔、主题按钮，扩展贡献的按钮也在这张清单里。
  • 🔵 批量归档：多选会话归档 / 恢复；侧栏提供「归档 7 天前」与「清理 30 天前归档」，删除项目全部会话时自动保留正在运行的。
  • 🟢 草稿与折叠：尚未落盘的会话标「草稿」；子会话与分支会话可分别折叠，长树不被撑开。
  • 🟢 Shift+点击直接删：删除会话默认二次确认，按住 Shift 点击跳过确认。

模型与后端选择

  • 🟢 模型行直接显示价格：模型选择器右侧显示目录里的即时代价提示（如 $0.6/$2.2 per M 输入/输出价），比价不用跳设置页。
  • 🟢 外部 agent 模型提示：模型行会标注 ext-agent 目录的接入提示，分得清哪个模型来自哪家。
  • 🟢 缺少的 CLI 直接置灰：后端下拉里没安装的 agent 会灰掉并给出原因，点「重新扫描」即可发现启动后新装的 CLI，不用重启工作台。
  • 🟢 模型向导可读性：提供商树可折叠 + 状态图例工具条，几十家提供商不再一屏糊脸。
  • 🟢 模型可见性规则：可配置的模型过滤、探测上限与发现缓存，长列表只留自己要用的。
  • 🟢 限流与异常徽标：模型行直接标 429 限流 / 探测异常 / 未测，provider 整体限流会合并成一条提示；只提示，不会偷偷禁用模型。
  • 🟢 运行中切模型「下轮生效」：不打断当前轮，徽标明示何时生效。

文件、队列与小工具

  • 🟢 文件查看器多标签：标签页支持拆成独立窗口、换停靠位置、按文件夹分组，预览状态在切标签后保留。
  • 🟢 队列可导出/导入：排队消息与恢复队列都能整份导出（Markdown / JSON），导入时能解析回来，换机或排错不用一条条抄。
  • 🟢 崩溃救援页：页面崩溃时给双语救援界面与紧急 AI 端点，先救数据再查原因。
  • 🟢 重启恢复：按 running-journal 里记录的中断会话清单扫描并编排恢复，重启后知道哪些会话被打断、该怎么接。
  • 🟢 首装自动配好脱敏插件：首次启动自动安装随包的第一方 pi 插件（默认 pi-secret-mask，随手贴不泄密）；跳过的插件会写清原因，不静默失败。
  • 🟢 扩展后台自愈：随包扩展在后台 reconcile，失败带冷静期，不会反复重试拖垮启动。
  • 🟢 输入框命令提示：输入占位符里提示可用命令，输入触发词后自动消费；文件面板也有「打开终端」命令卡。
  • 🟢 清空输入可撤销：清空即入回收站，撤销一键找回；误清不再等于重写。
  • 🟢 附件统一落工作目录：粘贴或附加的图片与文件存到 <cwd>/.pi-attachments/（自动加 .gitignore 隐藏），消息里以路径引用；重名不覆盖。
  • 🟢 手机输入矩阵与折叠：＋ 面板把模型 / 思考档位 / 工具预设 / 压缩 / 声音 / 队列 / 扩展状态与面板收在一处；输入区与队列可下滑折叠、上滑拉出。

扩展内部的体验细节

  • 🟢 消息智能弹层自适应：宽屏下操作弹层显示更多文本，窄屏折叠，文件操作行顺序也做了统一。
  • 🟢 分享接收点：分享对话框的内容可以「收藏为命令 / 存为提示词」，通过 share-sink 扩展点互相投递。
  • 🟢 分享目标可插拔：上传目标（Gitee / 图床 / 对象存储 / 笔记归档）不是硬编码，审计目录还能当远程 overlay 热更新。
  • 🟢 子代理折叠编队：Fleet 面板支持按编队折叠与并发数入口，代理多起来也能看清。
  • 🟢 设备面板重做：设备互连改成右栏停靠 + 设备详情浮层，连线状态一眼可查；消息仅存内存、文件 1h 自清、离线设备 1h 回收。
  • 🟢 跨桥联邦（默认关）：打开 pairFed.enabled 后可看到权威桥上 fed: 命名空间的设备并互发消息/文件，多实例不必各聊各的。
  • 🟢 朗读跟随来源：语音朗读会标注当前读的是哪个会话；长文本分块后逐段合成，不卡在超长输入上。
  • 🟢 本地 TTS 音色克隆：除浏览器 Web Speech 与 edge-tts 外，还能跑本地 ONNX TTS 引擎（Hojo-TTS-Light 40M/80M，CPU 即可），以 OpenAI 兼容服务对外，支持音色克隆。
  • 🟢 编辑器选区卡：跨预览（同源与跨域）都能用选区卡操作，编辑器工具条还有朗读入口。
  • 🟢 搜索结果带方案标签：会话搜索结果在服务端就带上是哪个方案相关的标签，筛选更快。
  • 🟢 隧道手机入口：服务隧道面板新增手机访问二维码入口，手机扫码即达；容器面板的端口页可直接跳转隧道配置。
  • 🟢 调试可归因：devtools 的交互记录会标出属于哪个 agent 会话与哪台设备，还支持跨桥联邦代理。
  • 🟢 agent 自带额度：aiti-qoder-agent 能查 credits 配额与 WASM 签名的模型目录，aiti-agent-manager 统一聚合各家登录态与账号额度。
  • 🟢 凭据只读给模型：pi-secret-vault 里模型只能 vault_list / vault_get 拿占位令牌，增删改与看明文始终由人操作（弱口令在新增/轮换时就报警并标 ⚠）。

说明：开发专用扩展不随发行版分发、不计入功能清单——aiti-crash-fatal（Fatal 崩溃测试，NODE_ENV !== development 直接拒，只部署到 dev 目录）、demo（全插槽演示扩展，框架验证用）。
