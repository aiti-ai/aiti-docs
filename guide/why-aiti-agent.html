为什么选 Web 工作台（aiti-agent）

一句话：把「发起任务、盯进度、审阅结果、切模型、看统计、跨设备接手」这些每天几十次的动作，从 IDE 窗口和终端里搬到一块常驻的、可远程的、可移动的操作面上——而代码、会话、工具仍然在你自己机器上。

先说清楚：这可能不适合你

如果你只是偶尔用 AI 写点东西，不要折腾这个——用你熟悉的工具就好，IDE 内置 AI、命令行 agent、桌面 App 都能干活。工具没有好坏，你能驾驭的那把就是好工具。

这个项目是按我个人的工作习惯和工作场景深度定制的。它不一定适合你。来历见项目起源。

三十秒判断

过去一周，下面五件事你碰到过几件？

判断项典型的形态痛点
同时开 2 个以上 agent（pi / Claude Code / Codex / Cursor…），来回切窗口找上下文IDE / CLI 各自一份历史，跨工具就断档
在手机上想看进度，只能 SSH 或等回到电脑前终端 / IDE 的小屏体验以查看为主，完整操作要回电脑
关掉本地 IDE / 终端窗口后，担心 agent 被打断本地 agent 的进程跟着窗口走（云 agent 除外）
想查「这个月花了多少 token、哪个模型最贵」，只能翻账单没有跨 agent 的成本数据面
想让 AI 直接看页面、点元素、改样式，只能截图粘贴终端和编辑器看不见渲染结果

≥2 件「是」，说明你的工作方式已经超出单窗口工具的承载范围——这正是 Web 工作台的设计中心。下文先给形态级对照，再解释机制与边界；全部结论都可以在文末「十分钟自测」里自己验证。

0–1 件「是」：关掉这页，继续用你现在的工具就好——真的没必要为了一个工作台改自己的工作方式。

对比口径：本文比较的是形态，不是某个具体产品。同一形态内部差异很大（例如同为 IDE，Cursor 与 JetBrains AI 就不同）；表格取该形态的典型能力，✅ 原生 / ⚠️ 部分或靠插件 / ❌ 基本没有。文中所有「N 家」都是今天内置的覆盖，不是能力上限。

二、大对照表

先说明三件事，避免误读表格：

  1. ✅ / ⚠️ / ❌ 只描述该形态「开箱默认」。⚠️ = 通常要靠插件、MCP、云服务或自己写扩展才能补到；❌ = 没有通用扩展点能补到同等程度——不等于永远做不到。
  2. 其他形态的扩展生态并不弱：IDE 有插件市场 + MCP + ACP，CLI 有插件 / 技能 / 钩子 / MCP，桌面有 MCP 扩展与连接器，自托管 Web 壳也在长。差距主要在归属与工具面，不在「有没有插件」。
  3. 我们的「N 家」同样不是封闭清单——它们是今天内置的覆盖，后面都能继续加，见 2.0。

上面这些差异只说明现有工具没有覆盖我的用法，不代表它们做不到或做得不好。它们各有各的强项，我只是按自己的需要补了一块。

没有的能力，有路可补：装 MCP server、装 pi 插件，或者按扩展 API 写一个工作台扩展（插槽 / 服务 / API 路由 / agent hooks）。前两条装上就用；写扩展用现成插槽即可，插槽不够再加热一个扩展点。

口径补充：现代 IDE 的 agent 常常一部分跑在厂商云（如 Cursor Cloud Agents、Copilot coding agent），Claude Code / Codex 也有云会话与移动端；表格把这些算进对应形态，而不是当作「Web 独有」。

小结：工具链的差别是广度 vs 深度。IDE 在编辑器、调试、重构上更深；这套工作台的广度在「agent 能动手的范围」——容器、虚拟桌面、隧道、Office、IM、设备互连不在 IDE 的职责里。页面注入也不是独占：任何能接 MCP 的宿主都能用 aiti-bridge，这里只是把它做成了内置面板。 表里标 ⚠️ 的两项（LSP / 通用调试器）也能靠 MCP 或扩展补一部分，但完整的 IDE 体验仍建议配 IDE。

2.6 内测与规划中的扩展（🟡 内测中 / 📋 规划中）

这些扩展还在实验区，接口与行为都可能变；列在这里是为了说明工作台能长到哪，不是交付承诺。标 🟡 的已可内测，标 📋 的还在方案评审、尚未实现。

  • CodeHub（aiti-codehub）——云效 / GitHub / Gitee / GitLab 的工作项与代码库统一入口：搜索、详情、评论、克隆、建分支 / 合并请求；多账号；aiti_codehub_* 工具 + skills。意义：把「需求 → 分支 → 会话」收进同一个工作台，代码托管不再是另一个浏览器标签页。

  • 视频工作室（aiti-video-studio）——scene.json 写脚本 → 确定性回放录制 → TTS 旁白 → ffmpeg 合成；光标 / 覆盖层 / 转场 / 字幕 / 多语言 / 9:16。意义：AI 只参与创作期、运行期零 AI，演示视频从手工录屏剪辑变成可重跑的流水线。见扩展页。

  • 模型网关（aiti-model-gateway）——把工作台已配置的模型导出成 OpenAI 兼容 API（chat/completions + tools、models、images），外部 CLI 用网关 token 接入。意义：让「跑其他 agent」不只共享会话，也能共享模型与凭据，外部 agent 看不到真实 provider key。

  • Updater（aiti-updater）——版本检查 → 升级触发 → 原地观察（SSE）→ 跳服务管理（停止 / 重启 / 注销 / 环境 / 日志）；服务注册、升级、服务管理统管，安装与反代通过 service-tunnels 配置收口。意义：把部署、升级与服务管理收进工作台的一个面板。

  • Proc Tree（aiti-proc-tree）· 📋 规划中——以 pi-web 宿主为根，把所有派生出来的子进程按树列出：终端（aiti-cmd）、隧道（service-tunnels）、子代理（subagents）、外部 agent（Pi TUI / ACP 后端）、detached 会话都能认领；带 CPU / 内存 / 时长，可结束单进程或整棵子树，形态对齐 Chrome 任务管理器。意义：跑飞的子进程不用再去 ps 里翻。当前状态是方案评审，尚未实现。

🟡 内测中的扩展只在实验区分发，未上架 npm、未随发行版，升级可能不兼容；CodeHub 的写操作（如建合并请求）默认关闭。📋 规划中的还在方案评审，尚未实现。

三、八个结构性理由

1. 运行位置：会话在服务里，不在窗口里

浏览器只是一个视图。关标签页、断网、换设备，agent 照常跑（厂商云 agent 也能做到后台，区别是跑在厂商沙箱而不是你的机器上）；停掉或重启 pi-web 服务本身也不必然打断正在跑的回合——detach 让 agent 由独立 wrapper 托管（Linux systemd-run / macOS 普通脱离进程 / Windows Win32_Process.Create），通过本地 socket 与服务通信，自带 4 MB 环形 journal——服务重启后重连，历史输出原样回放，空闲且无客户端附着的会话由 wrapper 回收。已接入：pi、ACP 全系、Claude Code、CodeBuddy、Cursor、Qoder、omp 等，其余后端陆续接入。详见架构 · 会话与 detachment。

2. 会话资产：一个索引覆盖 20+ 家 agent

session-manager 把 23 家 agent 的私有存储解析成统一模型（内置覆盖；第三方可用 session-agent-source 槽继续加），FTS5 trigram 支持中文全文检索，标签、收藏、归档快照、看板、分支 / worktree 分组都在同一侧栏。AI 自己也能搜：pi-session-search 给 agent 提供 session_search / session_read，上下文被压缩后可以翻回原文接着做。历史会话不是化石，点开就能续聊。

3. 输入是工作流

本地收藏 / 历史命中即灰字直出（零模型），未命中才走 AI 续写（系统听写 / 补全插件能补一部分，但很少把补全、命令、草稿、队列做进同一条链）；打「模型」「压缩」直接执行命令并回到输入流；按住说话有流式 ASR 与热词；草稿按会话共享、崩溃可恢复；队列在服务端持久化，能排序、插队、取回编辑、重启后逐条决议。见 aiti-ai-input、aiti-draft-keeper、aiti-queue-keeper。

4. 消息是界面对象

段落、标题、表格行、代码行都可点：复制、引用、A·B 选项、行高亮；顶部锚点告诉你「屏幕上这段是谁问出来的」，导航条一键到上一条 / 下一条 / 最早 / 最新；长回答还能切听书模式，按句高亮跟读。见 aiti-msg-smart、aiti-ai-speek。

5. 工具链长在同一页

真 PTY 终端（重启存活）、容器面板、虚拟桌面 VNC / RDP、服务隧道、文件 / Office / 文档中心、Git 审核与改动血缘、JVM 与 Windows 进程调试、子代理舰队、定时任务、IM 遥控——都是同一个工作台里的面板，和会话共享工作目录与运行上下文。这是「比 IDE 更丰富」的具体含义：不是编辑器功能更多（编辑器 / 调试仍是 IDE 更深），而是agent 能动手的范围更大。

6. 统计与治理要中心化

用量报表支持任意维度组合（workspace / provider / model / key / 时段 / 日期 / agent）× 多指标，三种视图 + CSV；外部 agent 的 token 也能摄入（第三方 ccusage 等能汇总一部分 CLI 用量，但不是与运行时会话同源的多维视图）；16 家 provider 余额与配额、模型健康探测、上下文与流畅度指示、每会话统计导出，再叠加密钥脱敏 / 保险库 / 配置回滚 / 数据快照。见 aiti-ai-usage。

7. 小屏满血，不是缩水版

手机不是「远程看一眼」的遥控器：触屏输入矩阵（模型 / 思考档 / 工具预设 / 压缩 / 队列 / 扩展状态收在一处）、输入框与队列下滑折叠、浮层自动全屏 + 系统返回关闭、右栏状态恢复、队列触摸拖拽、语音 + 「⏎ 换行」胶囊、TTS 跟读。PWA 安装态与离线能力仍在路线图上，这是当前明确的缺口。见 全功能小屏适配。

8. 页面就是 AI 的现场（aiti-devtools）

把调试客户端注入正在开发的页面：点选元素 → 结构化信息直达 AI；AI 可执行类 DevTools 的 DOM / CSS / 输入 / 性能操作，也能反过来请用户点选元素、回答问题。载体覆盖 Vite / webpack / Nuxt / Astro，另有浏览器扩展（任意站点）与 VS Code 扩展，桥协议统一。页面注入并非独占——任何 MCP 宿主都能接 aiti-bridge；这里只是把它做成了内置面板，并与工作台同源。 实验区还在长：CodeHub 把工作项和代码库接进来，视频工作室把演示视频变成可重跑的流水线，模型网关把已配置的模型借给外部 agent——都还是内测（见 §2.6）。见 aiti-devtools。

四、边界：它不做什么

一份可信的「为什么选」必须写清代价。以下都是已知边界，不是待修的 bug：

边界说明建议
不是 IDE没有 LSP 补全、断点调试、跨文件重构、测试面板深度改代码继续用 IDE；LSP / 调试可装 MCP 或写扩展补一部分；pi 会话与 IDE 同源，其他 agent 的会话可在 Web 侧继续
部署仍在收口安装 / 升级 / 反代正在由内测中的 aiti-updater 打通（依赖 service-tunnels），尚未随发行版现在可用 docker run 或一键脚本；转正后是面板里的事
浏览器有成本内存占用高于 TUI；超长会话依赖懒加载分页大会话用分页导航；服务端可跑在别的机器
单用户自托管没有多租户、团队协作、云同步多人场景自行做实例隔离与反代
移动端仍有余量触屏交互已完整，PWA 安装态 / 离线待推进用浏览器「添加到主屏幕」，依赖在线连接
后端适配是持续工程各家 CLI 的登录态、流式协议、历史格式都在变关注版本说明；不适配时仍可按普通会话使用
detached 有平台差异Linux / macOS / Windows 各有 runner，且并非所有后端都已接入用「托管模式」徽标确认当前会话是否可脱离
上游维护成本跟随 pi 与 pi-web 演进，偶尔需要处理上游变更使用正式发行版；自建时锁定版本

五、怎么组合使用

形态之间不是替代关系。推荐把 Web 当中心，其他形态当专用工具：

场景主力搭配
长时间任务、多 agent 编排Web 工作台CLI 用 /web 附着同一会话；手机看进度
深度编码、重构、断点调试IDEWeb 查历史会话、用量与改动血缘
一次性脚本、CI、低带宽环境CLIWeb 汇总用量与结果
页面联调Web + aiti-devtools浏览器扩展 / VS Code 扩展
无头服务器 / 远程机器Web（Docker）服务隧道 + TOTP + VNC / RDP
只想给一个 CLI 套个聊天窗CLI 兼容 Web够用即可；需要会话资产时再迁到工作台

兼容性是这个组合的前提：pi CLI、pi IDE 扩展与 Web 操作的是同一批会话文件，不是三套数据。你不需要「选边站」。

六、十分钟自测

不用看文档，按下面顺序做一遍就能判断它是否适合你：

  1. 起服务：npx --allow-scripts=@aiti-ai/pi-web @aiti-ai/pi-web@latest（或 docker run -d -p 30142:30142 aitiai/pi-web:core）。
  2. 开两个 agent：新建一个 pi 会话，再从侧栏接一个已安装并登录的 Claude Code / Codex 会话，确认它们出现在同一个项目树里。
  3. 换设备：手机浏览器打开同一地址（或经隧道），发一条消息、排一条队、改一次模型。
  4. 关浏览器：等 30 秒再打开，确认 agent 没停、输出还在。
  5. 重启服务：docker restart 或 systemctl restart，回来重新打开该会话；后端支持 detached 时会回放历史并继续。
  6. 看统计：打开用量报表，按 provider / model 切一次维度，导一份 CSV。
  7. 进页面：在任意 Vite 项目里装上 @aiti-ai/aiti-devtools-vite，点一个元素让 AI 改它的样式。

七步里如果有三步以上让你觉得「这个我每天都要用」，Web 工作台就是合适的中心；如果只对第 7 步有感觉，你需要的可能只是 aiti-devtools 而不是整个工作台；如果都不需要，也不必迁移——工具顺手比功能多重要。
